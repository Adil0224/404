# Ақниет емханасына жазылу сайты

Бұл репозиторийде GitHub Pages-тағы статикалық сайт және Node.js, Express, PostgreSQL негізіндегі API бар. Негізгі ақпараттық бет GitHub Pages-та ашылады. Docker арқылы іске қосылғанда пациент кабинеті, дәрігерлер каталогы, қабылдауға жазылу және қызметкер кабинеті Express/PostgreSQL API-імен жұмыс істейді. GitHub Pages статикалық болғандықтан, API функциялары сол ортада backend бұлтқа орналастырылғаннан кейін толық қосылады.

## Қосылған мүмкіндіктер

- **Frontend:** HTML, CSS және JavaScript; сайт GitHub Pages-та ашылады.
- **Backend:** `server/` ішіндегі Express API; `GET /api/health` сервер мен дерекқорды тексереді.
- **Дерекқор:** пайдаланушылар, рөлдер, сессиялар, дәрігерлер, филиалдар, жұмыс кестесі, бағалар, қабылдаулар және пікірлер кестелері.
- **Үлгі деректер:** 10 дәрігер, екі филиал, жұмыс кестесі және қызмет бағалары.
- **Авторизация API:** пациентті тіркеу, кіру және шығу; парольдер bcrypt арқылы хэштеледі. Токендер бір сағаттан соң бітеді, ал шығу сервердегі сессияны тоқтатады.
- **Рөлдер:** пациент, дәрігер және әкімші. Әкімші тіркелгісін бір рет орнату скрипті жасайды; дәрігер тіркелгілерін әкімші API арқылы ашады.
- **Қабылдау API:** қолжетімді кесте бойынша жазылу, көру, уақытын өзгерту немесе тоқтату. Бір дәрігерге бір уақытта екі белсенді жазылу жасалмайды.
- **Әкімші басқару беті:** `admin.html` арқылы дәрігерлерді, филиалдарды, қызмет бағаларын және апталық кестені қосу, өзгерту немесе уақытша өшіру. Әрекеттер Bearer токенімен қорғалған әкімші API-іне жіберіледі.
- **Іздеу және сүзгі:** дәрігерлерді аты, мамандығы және филиал бойынша API-ден іздеу, сұрыптау және беттеу.
- **Пациент кабинеті:** `portal.html` ішінде тіркелу/кіру, бос қабылдау уақытын көру, жазылу және өз қабылдауларын қарау.
- **Қызметкер кабинеті:** `staff.html` — дәрігер аккаунтымен кіру; тек сол дәрігерге тіркелген қабылдаулар көрсетіледі.
- **Бақылау:** `GET /api/health`, `GET /api/metrics` және сұрау ID-сімен JSON форматындағы сервер логтары.
- **Тексеру:** Node.js unit және API integration тесттері; `k6/clinic-load.js` жеңіл жүктеме сценарийі.

## Backend-ті жергілікті іске қосу

1. Node.js 20 немесе одан жоғары нұсқасын және PostgreSQL орнатыңыз.
2. PostgreSQL ішінде `akniet_clinic` атты дерекқор жасаңыз.
3. `server` бумасына кіріп, `npm install` орындаңыз.
4. `.env.example` файлын `.env` деп көшіріңіз. `DATABASE_URL` жолын өз базаңызға сәйкестендіріп, `JWT_SECRET` орнына кемінде 32 таңбалы кездейсоқ құпия мән қойыңыз. Оны жасауға болады:

   ```sh
   node -e "console.log(require('node:crypto').randomBytes(48).toString('hex'))"
   ```

5. Схеманы және үлгі деректерді кезекпен іске қосыңыз:

   ```sh
   psql -h localhost -U postgres -d akniet_clinic -f db/schema.sql
   psql -h localhost -U postgres -d akniet_clinic -f db/seed.sql
   ```

6. Әкімші тіркелгісін жасау үшін `.env` ішінде уақытша `ADMIN_NAME`, `ADMIN_EMAIL`, `ADMIN_PASSWORD` мәндерін толтырып, `npm run admin:create` орындаңыз. Құпиясөз кемінде 14 таңба болуы керек. Скрипт бір әкімшіні бір рет жасайды. Орындағаннан кейін `.env` ішінен осы үш уақытша мәнді өшіріңіз.
7. Серверді іске қосыңыз: `npm run dev`.
8. `http://localhost:3000/api/health` адресінен сервер мен дерекқор байланысын тексеріңіз.

`psql` командасы `.env` файлын автоматты түрде оқымайды. Жоғарыдағы командалар әдепкі `localhost`, `postgres` және `akniet_clinic` мәндеріне арналған; басқаша болса, өз базаңыздың хостын, пайдаланушысын және атауын қойыңыз. Өндірістік ортада `FRONTEND_ORIGINS` мәніне сайттың нақты доменін қосып, `DATABASE_SSL=true` орнатыңыз.

## Docker арқылы іске қосу

Docker Desktop орнатып, репозиторийдің негізгі бумасында:

```powershell
Copy-Item .env.docker.example .env
```

`.env` ішіндегі `POSTGRES_PASSWORD` және `JWT_SECRET` мәндерін өзгертіп, содан кейін:

```sh
docker compose up --build
```

Сайт `http://localhost:8080`, API `http://localhost:3000` адресінде ашылады. Пациент кабинеті `/portal.html`, қызметкер кабинеті `/staff.html` адресінде ашылады. API күйі: `http://localhost:3000/api/health`. Контейнер бірінші рет іске қосылғанда дерекқор кестелері мен үлгі деректер автоматты жасалады. Тоқтату үшін `docker compose down`; дерекқор деректерін де өшіру керек болса, `docker compose down -v` орындаңыз.

GitHub Actions push және pull request кезінде контейнерлерді жинап, API күйін, ашық API тізімдерін, веб-бетті және unit/integration тесттерін тексереді. `main` тармағына push өткенде GitHub Pages-ке статикалық сайтты жариялайды. GitHub-та **Settings → Pages → Build and deployment → Source → GitHub Actions** параметрін бір рет таңдау қажет. Backend бұлтқа әлі орналастырылмаған; оған бөлек хостинг және құпия мәндер қажет.

## Тест, лог және жүктеме тексеруі

Unit және API integration тесттерін іске қосу:

```sh
cd server
npm test
```

API сервері іске қосылып тұруы керек. Жүктеме сынағын k6 орнатқаннан кейін Docker/API адресін беріп орындаңыз:

```sh
k6 run -e API_URL=http://localhost:3000 k6/clinic-load.js
```

Сынақ шағын жүктемемен (5 виртуал пайдаланушы, 30 секунд) шектелген; өндірістік жүктеме сынағын хостинг иесінің рұқсатымен ғана жасаңыз. `/api/metrics` процесс іске қосылғаннан бергі HTTP сұрауларын Prometheus форматына ұқсас түрде береді. Бұл метрика процесс қайта жүктелгенде нөлден басталады.

## Бұлтқа орналастыру

`render.yaml` Render Blueprint жоба үлгісін береді: API контейнері мен PostgreSQL. Render Dashboard-тан осы репозиторийді Blueprint ретінде қосып, `FRONTEND_ORIGINS` мәніне `https://adil0224.github.io` енгізу керек. API іске қосылғаннан кейін GitHub репозиторийдің **Settings → Secrets and variables → Actions → Variables** бөлімінде `CLINIC_API_BASE` айнымалысын API-дің `onrender.com` адресімен жасаңыз. Келесі `main` commit Pages deploy кезінде оны автоматты түрде `api-config.js` файлына енгізеді. Render-дегі `FRONTEND_ORIGINS` мәні `https://adil0224.github.io` болуы керек. Бұл конфигурация аккаунтты өзі жасамайды және сервиске өзі deploy жасамайды. Render тарифтері мен шарттары өзгеруі мүмкін; іске қоспас бұрын Render Dashboard-тағы ағымдағы бағаны тексеріңіз. Blueprint үлгісі: [Render Blueprint құжаттамасы](https://render.com/docs/blueprint-spec).

## Негізгі API адрестері

- `POST /api/auth/register` — пациентті тіркеу; JSON: `fullName`, `email` немесе `phone`, `password`.
- `POST /api/auth/login` — кіру; JSON: `identifier`, `password`. Жауапта Bearer токені келеді.
- `GET /api/auth/me` және `POST /api/auth/logout` — токен арқылы аккаунтты көру және сессиядан шығу.
- `GET /api/doctors?q=&specialty=&branch=&page=&limit=&sort=&order=` — іздеу, сүзгі, сұрыптау және беттеу; `GET /api/availability?doctorId=&branchId=&serviceId=&date=` — бос уақыттар; `GET /api/branches`, `GET /api/services` — ашық тізімдер.
- `GET /api/metrics` — процесс ішіндегі сұрау санағы; `GET /api/health` — API және PostgreSQL күйі.
- Пациент беті: `https://adil0224.github.io/404/portal.html`; қызметкер беті: `https://adil0224.github.io/404/staff.html`. Pages API серверін жүргізбейтіндіктен, бұл беттер тірі дерек алу үшін API хостингін талап етеді.
- `GET /api/appointments?page=&limit=&sort=&order=` — рөлге сай сұрыпталған және беттелген жазылулар.
- `POST /api/appointments`, `GET/PATCH /api/appointments/:id` — пациенттің жазылуларын басқару.
- `/api/admin/doctors`, `/api/admin/branches`, `/api/admin/services`, `/api/admin/schedules` — әкімшіге арналған басқару API-лері.
- `POST /api/admin/staff` — дәрігерге қызметкер аккаунтын ашу және профильмен байланыстыру.
- Әкімші панелі: `https://adil0224.github.io/404/admin.html`.

Қорғалған API-лерге `Authorization: Bearer <token>` тақырыбын жіберіңіз. Әкімші тіркелгісін жасау үшін `admin:create` скриптін орындаңыз.

## Маңызды шектеу

GitHub Pages статикалық сайтты ғана көрсетеді. Тірі тіркелу, жазылу және қызметкер деректерін интернетте қолдану үшін Render Blueprint-ті өз аккаунтыңызда іске қосып, API доменін сайтқа байланыстыру қажет. Нақты пациенттердің медициналық деректерін оқу жобасының демо нұсқасында сақтамаңыз.
